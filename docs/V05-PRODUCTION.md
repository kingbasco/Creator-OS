# V05 — The 5 Layers Behind Every AI-Built App

76-second visual explainer, eight scenes.

## Visual direction
Continue the approved V04 motion language: original illustrated presenter, Geist typography, clean off-white canvas, Creator OS blue accent, interface components that actually move, and transitions where objects carry the explanation forward. Do not restore the removed top branding labels.

The core visual metaphor is one app being physically separated into five stacked layers:

1. Interface
2. Application logic
3. API / backend
4. Data + identity
5. Infrastructure / deployment

The strongest sequence is the login example. A user taps **Log in** on the interface. The request becomes a moving packet and travels downward through each layer. Authentication and data return a result, then the packet reverses direction and the interface changes to a signed-in state.

## Scene plan
- S01: start with one polished app screen, then pull the screen upward and reveal four hidden layers underneath.
- S02: isolate the interface and animate form fields, a button and feedback state.
- S03: turn the button click into an application-logic decision tree.
- S04: transform the decision into an API request moving through a backend service.
- S05: split the backend destination into authentication, permissions and database records.
- S06: zoom farther out to reveal deployment/runtime, environment variables, logs and availability around the stack.
- S07: recombine all five layers and animate one complete login request down and the response back up.
- S08: show three example bugs attaching to different layers, then highlight the correct layer instead of treating the whole app as one box.

## Production rules
The presenter should support the explanation rather than cover the diagrams. Keep the presenter in a lower corner and use pointing/reaction poses only when they direct attention. Prefer real UI behavior, packets, state changes and transforming cards over static labels. No narration generation until the full visual direction is approved. Reuse the existing Tesseract/Remotion assets and avoid new paid services.
